# AGENTS.md — Financial Decision Lab (FDL) Developer & AI Agent Guide

Welcome, AI Agent! This document is your comprehensive operational guide for working on the **Financial Decision Lab (FDL)** codebase. Follow these rules, invariants, and patterns whenever reading, creating, modifying, or testing code in this repository.

---

## 1. Executive Summary & Core Mission

**Financial Decision Lab** is a personal finance assistant designed around one core premise:
> *"Can I afford this next month?"* — A system that proves every calculation, shows its work step-by-step, refuses to hallucinate, and explicitly communicates uncertainty (P10 / P50 / P90).

### Key Product Pillars
1. **Deterministic Financial Math**: Every number, calculation, forecast, and verdict is computed strictly by deterministic Python/TypeScript code. The LLM **never** calculates balances, headroom, buffers, or verdicts.
2. **Explainability & Reasoning Ledger**: Every decision produces an audit trail of discrete steps (`LedgerStep`) linking starting balances, expected cash flows, recurring obligations, variable spend, safety buffers, and headroom.
3. **Number-Verification Guard**: Any natural-language explanation generated by an LLM is validated by a strict regex guard ensuring every numerical figure cited exists verbatim in the Reasoning Ledger.
4. **Data Sufficiency Gate ("Say When It Doesn't Know")**: If data is insufficient (< 90 days history, large gaps > 7 days, missing income credits, or unreconciled balances), the system refuses to make ungrounded claims and produces an actionable remediation checklist.
5. **Local-First & Privacy Preserving**: By default, financial transactions, account numbers, and statement text never leave the user's machine (`PRIVACY_MODE=local`). All external egress is logged in the `egress_log` table.

## 2. Non-Negotiable Invariants (Golden Rules)

When writing code, you **MUST** adhere to the following 7 golden rules:

| Rule | Description | Violation Consequence |
|---|---|---|
| **1. Integer Paise Only** | All monetary amounts must be stored and computed in **integer paise** (`MinorAmount` / `BigInteger`). ₹1.00 = 100 paise; ₹80,000.00 = 8,000,000 paise. | Floating-point rounding drift (Instant bug rejection). |
| **2. Signed Amounts** | In transactions, **Credits (inflow) are positive (`> 0`)**, and **Debits (outflow) are negative (`< 0`)**. | Inverted cash flows and corrupted ledger math. |
| **3. Date Format** | All dates must be ISO 8601 string `YYYY-MM-DD`. Timestamps in UTC ISO format `YYYY-MM-DDTHH:MM:SSZ`. | Incompatible string sorting and date comparison bugs. |
| **4. Zero Math in LLM** | LLMs are restricted strictly to: parsing user queries into parameters, and translating structured ledger outputs into plain English narration. | Hallucinated figures and unprovable advice. |
| **5. Number Guard** | When generating natural-language narration, run `verify_numbers_in_ledger(narrative, ledger)`. If any number fails to match, fallback to deterministic template text. | False claims shown to user. |
| **6. Sufficiency First** | Always verify the `SufficiencyReport` before producing an `AffordabilityVerdict`. If `status == 'INSUFFICIENT'`, return verdict `INSUFFICIENT_DATA`. | Giving financial advice on blind/missing data. |
| **7. Reproducibility** | All stochastic operations (e.g. Monte Carlo simulations) must accept a random seed (`seed: int = 42`) for 100% deterministic reproducibility. | Inconsistent tests and untraceable verdicts. |

- **Validation**: Pydantic `>= 2.10.0`

- **Language**: TypeScript 5.7+

- **Icons**: Lucide React
- **Charts / Visualizations**: Recharts 2.15+
- **State Management**: Zustand 5.0+

## 6. Code Style & Implementation Patterns

### 6.1 Python Backend Guidelines

1. **Always Type Annotate**: Use standard Python type hinting (`int`, `str`, `float`, `list[str]`, `dict[str, Any]`, `Optional[int]`).
2. **Pydantic v2 Models**: Use `BaseModel` for request/response validation. Always define amounts as `int` (paise) with clear docstrings or field descriptions:
   ```python
   class AffordabilityQuery(BaseModel):
       purchase_amount_minor: int  # Amount in paise (e.g. 8000000 for ₹80,000)
       label: str = "Purchase"
       timing: str = "next_month"  # "next_month" | "this_month"
       payment_type: str = "cash"  # "cash" | "emi"
       emi_months: Optional[int] = None
       emi_interest_rate_pct: Optional[float] = None
   ```
3. **Database Sessions**: Always inject the database session using `db: Session = Depends(get_db)`. Do not manage raw SQLite connections manually.
4. **Deterministic Random Seeds**: When calling numpy or scipy random functions (e.g. Monte Carlo samplers), always allow passing a seed:
   ```python
   def simulate_cash_flow(daily_flows: np.ndarray, n_runs: int = 5000, seed: int = 42) -> dict:
       rng = np.random.default_rng(seed)
       ...
   ```

### 6.2 TypeScript Frontend Guidelines

1. **Import Shared Types**: Always import contracts, domain constants, and currency utilities from `@fdl/shared`:
   ```typescript
   import { MinorAmount, AffordabilityVerdictCode } from '@fdl/shared';
   import { formatINR, paiseToRupees, rupeesToPaise } from '@fdl/shared';
   import { DOMAIN_CONSTANTS } from '@fdl/shared';
   ```
2. **Displaying Currency**: Never format paise manually with `amount / 100`. Always use `formatINR(paise, showPaise)` which applies Indian grouping (lakh/crore) and rupee symbol `₹`.
3. **Next.js 14 App Router**: Place route components in `apps/web/src/app/`. Mark components with `'use client'` only when they need browser state, events, or Zustand stores.
4. **Tailwind Dark Palette**: Stick to the slate theme (`bg-slate-950`, `bg-slate-900`, `border-slate-800`, text `text-slate-100`, accents `emerald-500`, `indigo-500`, `amber-500`, `rose-500`).

## 7. Step-by-Step Feature Implementation Recipes

### Recipe A: Adding a Financial Engine Module
1. Check mathematical specs in [`docs/DOMAIN_ENGINE_SPEC.md`](file:///docs/DOMAIN_ENGINE_SPEC.md).
2. Create the calculation module in `apps/api/engine/<module_name>.py`.
3. Accept raw numbers in minor units (`paise: int`).
4. Return structured dataclasses or dicts containing: computed values, percentile ranges, and `LedgerStep` records.
5. Add unit tests in `apps/api/tests/test_<module_name>.py` verifying against edge cases (zero balance, single transaction, leap year, large numbers).
6. Expose via the appropriate router in `apps/api/routers/`.

### Recipe B: Adding a Statement Parser
1. Create `apps/api/parsers/<bank>_parser.py`.
2. Extract: `posted_date` (ISO), `raw_description`, `amount_minor` (signed integer), and `balance_after_minor`.
3. Calculate file SHA-256 for idempotent imports.
4. Run balance reconciliation:
   $$\text{Opening Balance} + \sum \text{Transactions} \stackrel{?}{=} \text{Closing Balance}$$
5. If reconciliation matches within tolerance, status is `PASSED`; otherwise flag `DISCREPANCY` with delta.

### Recipe C: Implementing the Number-Verification Guard
1. When generating LLM text in `apps/api/ai/narrator.py`:
2. Extract all numbers formatted as currencies, percentages, or integers from the generated text using regex.
3. Compare against the set of valid numbers in the associated `Reasoning Ledger`.
4. If an unverified number appears, reject the generated text and return deterministic template string.

## 8. Common Gotchas & Traps to Avoid

1. **Do not use floating-point for money**: Storing `₹199.99` as `199.99` in Python float will lead to `199.990000000000009` errors in cumulative sums. Always use `19999` integer paise.
2. **Debit vs Credit sign reversal**: In Indian bank statements, "Withdrawal" or "Debit" is negative money for the user. Do not store debits as positive numbers in the `Transaction` table.
3. **Internal Transfers**: A transfer between the user's HDFC savings account and SBI savings account is NOT an expense or income. If an internal transfer is not paired and excluded from cash flow, expenses will be double counted!
4. **Sufficiency Refusal is NOT a 500 error**: When a statement has < 90 days of history, this is expected behavior. The API must return HTTP 200 with `verdict.code = "INSUFFICIENT_DATA"` and `gate.status = "INSUFFICIENT"`, providing the user with missing items and fix actions.
5. **FastAPI CORS & Trailing Slashes**: Ensure routes match the exact frontend path (`/api/affordability` vs `/api/affordability/`).
